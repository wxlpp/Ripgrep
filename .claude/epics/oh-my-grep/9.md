# Task: Memory limits and streaming search API

## Description
Bound memory on the one-shot path and add a streaming API with back-pressure. High risk: concurrency + public API.

## Acceptance Criteria
- [ ] `Options.maxColumns: Int? = 4096`: lines cut to UTF-8-boundary prefix; match gets `lineTruncated`; submatches ending past the cut dropped
- [ ] `Options.maxMatches` default 10_000 (Swift default and Tool default); nil disables
- [ ] Multiline heap limit 64 MiB; over-limit file → warning
- [ ] Rust `SearchSession` (UniFFI Object): new(request, timeout) spawns walker thread; bounded channel; `next_batch(max) -> Option<Vec<SearchMatch>>` blocks until batch/finish; `cancel()`; `summary()` after exhaustion (cancelled, truncated, files_searched, elapsed, warnings); drop cancels and joins
- [ ] Swift `OhMyGrep.stream(pattern:in:options:) -> AsyncThrowingStream<Match, Error>`; consumer Task cancellation cancels session; request errors surface as stream error
- [ ] Tests: stream yields same match set as search; cancellation stops early; maxMatches honored; no deadlock when consumer stops early
- [ ] Measured: stream over 40 MB/400k-match log peak RSS < no-match baseline + 64 MB; one-shot wall time within 10% of 0.14 s

## Technical Details
Channel capacity in matches (e.g. 1024). Sink generic over sender. Walker thread panics → InternalPanic via panic_safe. `next_batch` is a blocking FFI call; Swift calls it from a detached task, never from the cooperative pool.
